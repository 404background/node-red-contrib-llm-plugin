# キャンバスレイアウト

Node-RED ノード配列のためのスタンドアロンなレイアウトエンジン。UMD モジュール
(`window.LLMPlugin.CanvasLayout` / `require('./canvas_layout.js')`)。
幅を考慮する: 鎖は `(widthA + widthB)/2 + edgeGap` で詰められ、幅の広いラベルは
隣接ノードを自動的に押し出す。

## 例

### 1. 全体再レイアウト(full reflow)

```js
const Layout = require('./canvas_layout.js');
const flow = [
    { id: 'a', type: 'inject',   wires: [['b']] },
    { id: 'b', type: 'function', wires: [['c']] },
    { id: 'c', type: 'debug',    wires: [] }
];
Layout.reflowCanvasNodes(flow, { startX: 100, startY: 100 });
// inject=120, function=140, debug=120 (grid-snapped from estimate)
// leftEdges:    a=100,         b=260 (=100+120+40),  c=440 (=260+140+40)
// x (centres):  a=160,         b=330,                c=500
// y all 100 (single row, single component)
```

### 2. 既存の2ノードの間にノードを挿入

```js
const merged = [
    { id: 'a', type: 'inject',   x: 100, y: 100, wires: [['n']] },
    { id: 'n', type: 'function', wires: [['b']] },                  // new (140-px wide)
    { id: 'b', type: 'debug',    x: 280, y: 100, wires: [] }
];
Layout.placeAddedNodesNearNeighbors(
    merged,
    { a: true, b: true },
    { a: { x: 100, y: 100 }, b: { x: 280, y: 100 } }
);
// a stays at 100, n placed centre 270 (left edge 200 = 100+60+40), then
// Step 3.4 shifts b right so its left edge sits at n.right+40=380 (b.x=440).
```

### 3. 純粋なトポロジカル位置(ピクセルなし)

```js
const positions = Layout.layoutNodes(
    ['a', 'b', 'c'],
    { a: ['b'], b: ['c'], c: [] },
    { a: [], b: ['a'], c: ['b'] }
);
// { a:{col:0,row:0,comp:0}, b:{col:1,row:0,comp:0}, c:{col:2,row:0,comp:0} }
```

## 公開 API

| 関数 | 用途 |
|----------|---------|
| `layoutNodes(aliases, outgoing, incoming, maxColumns?)` | 純粋なトポロジカルレイアウト。`{ alias: { col, row, comp } }` を返す。 |
| `reflowCanvasNodes(nodes, options?)` | キャンバス全体の再レイアウト(全位置を再計算)。 |
| `placeAddedNodesNearNeighbors(nodes, existingIdMap, basePositions, options?)` | 増分レイアウト(既存ノードは固定し、新規のみ配置)。 |
| `estimateNodeWidth(node, options?)` | ラベルベースの幅推定。`gridSize` にスナップ。 |
| `getNodeWidth(node, options?)` | `options.getNodeWidth(node)` があればそれ、なければ `estimateNodeWidth`。 |
| `computeComponentYOffsets(ids, positions, startY, spacingY, gap, nodeHeight?)` | 縦積みのためのコンポーネントごとの Y オフセット。`spacingY` と `gap` はエッジ間。行ピッチは `nodeHeight + spacingY`、コンポーネントステップは `nodeHeight + gap`。`nodeHeight` のデフォルトは `LAYOUT_DEFAULTS.nodeHeight`。 |
| `LAYOUT_DEFAULTS` | デフォルト定数。 |

## デフォルト

```js
LAYOUT_DEFAULTS = {
    startX:         60,
    startY:         60,
    spacingY:       40,    // edge-to-edge clearance between stacked node rows
    componentGap:   80,    // edge-to-edge clearance between disconnected components
    edgeGap:        40,    // edge-to-edge clearance between adjacent node edges (horizontal)
    minNodeWidth:  100,    // Node-RED MIN_NODE_WIDTH
    nodeHeight:     30,    // Node-RED's standard rendered node height
    gridSize:       20,    // Node-RED canvas grid (used by width estimate + comment stacking)
    maxColumns:      5
};
```

`spacingY`, `componentGap`, `edgeGap` はすべて**エッジ間**のクリアランス(可視の余白)を
表し、中心間距離ではない。レイアウトエンジンは中心座標が必要になるたびに内部で
`nodeHeight` を加えるので、`spacingY = 40` は連続する行の間にちょうどグリッド2マス分の
縦クリアランスを生む。

導出された `node.x` / `node.y` 座標は `gridSize` にスナップ**しない**。中心をスナップすると
可視の整列が歪む: 幅が `gridSize` の奇数倍のノード(例: 100 または 140px 幅)は、偶数倍
(例: 120px)のノードに対して左端が半グリッドずれてしまう — 両者が同じ列を共有すべきときでも。
代わりにエンジンは**左端**(構成上つねにグリッドの倍数)をスナップし、各中心を
`leftEdge + width(node) / 2` として計算する。これにより列内の兄弟ノードは、ラベル幅に関わらず
同じ左端を可視的に共有する。同じロジックで、縦方向の間隔には一様な
`rowPitch = nodeHeight + spacingY` が得られる。

コメントのスタックは `ceil(nodeHeight / gridSize) * gridSize`(デフォルトで = 40px)の
ステップを使う。これにより `nodeHeight`(30)がグリッドの倍数でなくても、コメントのスタックは
一定の視覚的リズムで上がる。コメントはその**左端**がアンカー対象の左端に一致するよう配置される
(`commentX = target.leftEdge + commentWidth / 2`) — 追加のスナップなし — ので、幅の広い
キャプションが軸から外れず、見出す列の下に可視的に揃う。

すべてのレイアウト関数は、これらの既定値を上書きするオプションを受け取る。増分レイアウトは
さらに、どこにも繋がらない新規ノードをまとめて置く帯の間隔として `bandGap`(既定は
`componentGap` と同じ)を受け取る。またどちらの関数も「何をキャンバス上の実体とみなすか」の
判定を差し替えられる(既定はタブ定義とサブフロー定義以外をすべて対象とする)。

両方の入口は最後に**上端のはみ出し防止**を通る。コメントのスタックは対象ノードから上へ伸びるので、
キャンバス上端に近いノードにキャプションを足すと、画面の外へ出てしまうことがある。いずれかの
ノードの上端が既定の余白(20px)より上に来てしまった場合は、全ノードを同じ量だけ下へ平行移動する。
相対的な位置関係は保たれ、フロー全体が下へスライドするだけである。位置を固定したまま1つの
コンポーネントだけを組み直す処理はこの防止をスキップする。呼び出し元が最後にキャンバス全体を
まとめて見るためである。

## 幅を考慮した間隔

```
distance(a, b) = (width(a) + width(b)) / 2 + edgeGap
```

幅は、まず呼び出し元が差し込んだ取得方法を試し、なければラベルからの推定に落とす。この差し込みが
あるおかげで、呼び出し元はエディタが実測した幅を渡せる。正確な幅が分かれば、隣り合うノードの
あいだにはラベルの長さによらず、ちょうど指定した余白(既定でグリッド2マス分)が空く。推定に落ちた
場合の式は、エディタ自身の描画コードのものを写している(Node-RED 4.1.7 で確認):

```
w = max(node_width, 20 * ceil((labelTextWidth + 50 + (inputs>0 ? 7 : 0)) / 20))
```

文字ごとのテキスト幅推定(ラテン ~7.5px、CJK / 全角 ~14px)＋ノード型依存の chrome を使う:

- **通常ノード**(inject, function, debug など): chrome = 57px
  (エディタの 50px chrome + 7px の入力ポートスタブ。入力なし型では ≤7px で、グリッドスナップに
  吸収される)。
- **コメントノード**: chrome = 24px — 実際に描画されたコメントに経験的に合わせた値である
  (アイコンが小さく、ポートの出っ張りもない)。ここを大きくすると、幅の広いキャプションが
  対象ノードの左端より右へ押し出されてしまう。

インポート時の既定である `edgeGap = 40` では、既定名のままの約 120px のノード2つは中心間で
約 160px に並び、あいだにグリッド2マス分の余白が残る。ユーザーが Node-RED でノードを1つずつ
ドラッグして置いたときにできる間隔とほぼ同じである。

## コメント配置

各コメントは対象キャンバスノードの直上に配置される:

- **縦方向**: 対象の上端に**グリッドギャップなし**で接触(中心間の差 = `nodeHeight` = 30px)。
- **横方向**: コメントの**左端**が対象の左端に一致
  (`commentX = target.leftEdge + commentWidth / 2`)。これにより幅の広いキャプションが、対象の
  狭い中心に中央揃えされるのではなく、見出すノードと同じ列に座る。

コメントごとの対象選択:

1. **明示的な指定** — スキーマがコメントの貼り付け先ノードを名前で指定している場合。インポート側が
   その名前を実ノード ID へ解決し、レイアウトはそれをそのまま使う。指定先は、同じスキーマ内の
   新規ノードでも、すでにキャンバスにある既存ノードでもよい。
2. **フォールバック** — 貼り付け先の指定がないコメントについては、変換時に記録しておいた宣言順を
   使い、そのコメントの次に現れるキャンバスノードを対象とみなす。

同じノードを対象とする複数のコメントは、互いに接するように上へ積み上がる。積み上げの際は、
すでにキャンバス上でその対象の直上にある**既存の**コメントも数に入れる。新しいコメントが既存の
積み重ねに重ならず、その上に乗るようにするためである。

**貼り付け先の指定がない末尾のコメントは落とされる。** 変換の段階で、指定がなく、かつ宣言順で
後ろにキャンバスノードもないコメントを取り除いているので、レイアウトに届く時点ではすべての
コメントが解決可能な対象を持っていることが保証される。貼り付け先を指定したコメントは、スキーマの
どこに書かれていても保持される。

## 各パスの詳細

### `layoutNodes` — トポロジカル位置

1. **コンポーネント分け** — 接続を向きなしとみなして幅優先探索し、繋がったノードのかたまりを求める。
2. **列** — 各かたまりの起点から接続の向きに沿って幅優先探索し、1つ進むごとに列を1つ増やす。
3. **行** — 最初の列は上から順に並べる。以降の列は「親たちの行の平均」を目標にし、そこが埋まって
   いれば空いている行が見つかるまで1つずつずらす。
4. **折り返し** — 列数の上限を超えた鎖は、決まった行数の帯に折り畳む。
5. **積み上げ** — かたまり同士は行番号の上で隙間なく詰めておき、実際のピクセル間隔は後段で与える。

### `reflowCanvasNodes` — 全体レイアウト

1. キャンバス上の実体だけを残して絞り込む。
2. 各ノードの接続配列から、前後の隣接関係を組み立てる。
3. トポロジカルな位置(列・行・所属するかたまり)を求める。
4. **左端を親から決める** — 各かたまりを列の順に、親を先に処理しながらたどる。各ノードは、
   すでに置かれた親があれば「親たちの右端の最大値 + 横の余白」を左端にし、親がなければ
   キャンバスの開始位置を左端にする。
   - どのかたまりでも列0のノードは同じ開始位置を共有するので、各フローの先頭ノードが左端に揃う。
   - 同じ親から枝分かれした兄弟は、その親の右端に余白を足した同じ左端を共有するので、これも揃う。
   - 鎖の下流ノードは**その鎖自身の**幅だけで進んでいくので、並行する別のフローに幅広のラベルが
     あっても、こちらの鎖が右へ引きずられることはない。
5. かたまり同士を、指定した縦の余白ぶんだけ縁と縁を空けて積み上げる。
6. 各ノードの中心座標を「左端 + 幅の半分」、縦位置を「行番号 × 行ピッチ + 所属かたまりの縦オフセット」
   として確定する。
7. 最後に、先頭に置かれるコメントを対象ノードの上へ配置し直す。

#### 具体例: 幅の異なる並行フロー

`edgeGap = 40`, `spacingY = 40`, `componentGap = 80`, `startX = 200`, `startY = 200`。
Flow A は幅広ラベル、Flow B は狭い。

| Node | width | leftEdge | x (centre) | y |
|------|------:|---------:|----------:|--:|
| `a1` (inject, "Sensor")                | 120 | 200 | 260 | 200 |
| `a2` (function, "Compute aggregated…") | 320 | 360 | 520 | 200 |
| `a3` (debug)                           | 120 | 720 | 780 | 200 |
| `b1` (inject)                          | 120 | 200 | 260 | 310 |
| `b2` (function, "fn")                  | 100 | 360 | 410 | 310 |
| `b3` (debug)                           | 120 | 500 | 560 | 310 |

`b3` は leftEdge 720 ではなく 500(= 360 + 100 + 40)に着地する — Flow A ではなく Flow B 自身の
幅に従う。`a1` と `b1` は leftEdge 200 を共有し、`a2` と `b2` は leftEdge 360 を共有する(どちらも
デフォルト幅 inject の下流)。より深い列では分岐する。Flow A の下端(215)と Flow B の上端(295)の
縦ギャップはちょうど `componentGap = 80` px。

### `placeAddedNodesNearNeighbors` — 増分レイアウト

`rightEdge(p) = p.x + width(p)/2`、`leftEdge(s) = s.x - width(s)/2`。

| Step | 内容 |
|------|--------------|
| 1 | 既存ノードを、編集前に保存しておいた座標へ戻す。 |
| 2 | キャンバス上の実体すべてから、前後の隣接関係を組み立てる。 |
| 3 | 新規ノードを、すでに置かれている隣接ノードの脇へ順に置く。前も後ろも繋がっていれば、前のノード群の右端に余白を足した位置に置き、縦は前後の平均の中間にする。前だけなら前のノードの右上、後ろだけなら後ろのノードの左上に置く。 |
| 3.4 | 新規ノードと、その後ろに繋がる既存ノードの組を見て、新規ノードの右端＋余白が既存ノードの左端を越えていたら、その既存ノードから接続の向きに沿って前方へたどり、届いた各ノードを必要な分だけ右へずらす。経路が合流する場合はずらし量の大きい方を採る。ここで動かしたノードは記録しておき、後段の押し下げ判定へ渡す。 |
| 3.5a | **同じかたまりの中での押しのけ** — 新しく置いたノードが、**同じかたまりに属する**既存ノードと横に近すぎ、かつ縦もほぼ同じ高さにあるなら、行ピッチ1つ分だけ下へ押す。変化がなくなるまで繰り返す。別のかたまりとの衝突はここでは意図的に無視する(次の段で扱う)。 |
| 3.6 | **挿入したフローの組み直し** — 新規ノードをうまく既存の鎖に繋げられたかたまりについて、位置を固定したままそのかたまりだけを組み直す。現在の左上を保ったまま全体レイアウトを適用し、意図しない折り返しが起きないよう列数の上限は外す。その結果、同じかたまりの中ではユーザーが置いた既存ノードも動く。挿入されたノードに幅を考慮した一定のリズムを与えるには、これしか方法がない。どこにも繋がらなかった新規ノードは対象外で、次の段でまとめて配置される。「接続したら必ず組み直す」という挙動はユーザーとの取り決めである。前段の安価な押しのけが先に走っているので、この段は常にまともな初期状態から始まる。 |
| 3.5b | **かたまり同士の押し下げ** — 現在の接続関係でノードをかたまりに分ける。新規ノードを含むか、直前の段で右へずらされたノードを含むかたまりを「変更済み」とみなす。変更済みのかたまりごとに、外形が縦横とも重なっていて、かつ上端がそれより下にある未変更のかたまりを集める。集めた全体に対して**一律の**下げ幅を1つだけ求め、同じ量だけまとめて下げる。下げ幅は「変更済みの下端＋帯の余白」から「集めた中で最も上にある上端」を引いた値で、外形は縁で測るので余白はちょうど縁と縁のあいだに効く。**この段でコメントは動かさない。** コメントは後段で対象ノードに追随するか、独立しているならその場に留まる。押し下げられたかたまりは次の繰り返しで押す側にもなる(連鎖する)。完全に上側から始まっているかたまりは決して押されない。動かす向きは下だけである。 |
| 4 | どこにも繋がらなかった新規ノードは、すでに置かれた全ノードより下に、独立したグラフとして改めて配置する。この帯の最初の行は、直前のフローの下端との間にちょうど帯の余白ぶんの隙間が空く位置に来る(前段の押し下げと同じ計算である)。横方向は、すでに置かれたノード群の**最も左の左端**(最も左の中心ではない)から始める。**コメントはこの帯には決して入れない。** キャプションは持ってきた座標のままか、最後のコメント配置でスキーマ指定の対象の上へ置かれる。 |
| 5 | **重なりの最終確認** — 全ノードの組み合わせを見て、まだ箱が重なっていれば下側をさらに下げる。ここは**かたまり単位で剛体として扱う**。かたまりの対応表を受け取っているので、2つのフローのあいだに残った重なりは、下側のかたまりを**丸ごと**平行移動して解消する。ユーザーが編集していないフローからノードを1つだけ引き剥がして形を崩すことはなく、同じかたまりの中の組み合わせには手を出さない。ここでもコメントは対象外である。 |
| 6 | **コメントの追随** — 元々キャンバスノード(またはその上に積まれた別のコメント)に*接していた*コメントを、そのノードの新しい位置へ、元の相対位置を保ったまま貼り直す。独立したコメント — 最も近い対象より明らかに下にあるか、その描画範囲から外れているもの — は追随させず、ユーザーが置いた場所に留める。 |
| 7 | **最後のコメント配置** — スキーマで新しく追加されたコメントを、解決済みの対象ノードの上に置く。帯に置かれたものも含め、すべての対象が最終座標を持ったあとに行う。 |

#### 保証: 未編集フローは平行移動のみ

追加されたノードも、横へずらされたノードも**含まない**かたまりは、組み直されることも形を崩される
こともなく、**剛体として一律に平行移動される**だけである。組み直しの対象になるのは、編集された
かたまりだけである(Step 3.6)。他のフローはすべて、かたまり同士の押し下げ(Step 3.5b)で、あるいは
それでも残った重なりについては剛体扱いの最終確認(Step 5)で、丸ごと下へ動く。これにより、隣接する
フローに編集がたまたま重なっても、ユーザーが丁寧に配置したフローの形はそのまま保たれ、単に隣が
下へずれるだけになる。

#### 増分レイアウトでの列数上限

増分レイアウトも列数の上限オプションを受け取るが、増分モードでは呼び出し元は通常これを無効にし、
既存のフローの形を保つ。新しく挿入された鎖は行を折り返さず、右へ伸びていく。上限を効かせるのは、
どこにも繋がらない新規ノードをまとめて置く帯(Step 4)だけである。そこは独立した新しいグラフを
形成するからである。インポート側もこの慣習に従い、まったくの新規フローのときだけ上限つきの
全体レイアウトを通し、既存フローの編集では上限を外した増分レイアウトを通す。

#### 具体例

デフォルト名のノード(inject=120, function=140, debug=120)、`edgeGap = 40`:
